            ACCESS SHARE. What is Aurora-specific here is the commit path, not the
            lock path: IO:XactSync and IO:AuroraStorageLogAllocate,
            because Aurora moved durability into the storage tier.

Module 3 · Port the tool contracts

    
The tool contract moves; the retrieval authority does not.

    
One canonical service, three transports. Aurora PostgreSQL still owns retrieval, fusion, ACL enforcement, traversal, citations and the receipt. AgentCore Gateway supplies a managed MCP surface and nothing else. Participants verify a pre-provisioned target — they do not create a Gateway, configure IAM or OAuth, or deploy Runtime.

  


  


  

    

      
Tool set · seven operations

      
Select an operation to see its resolved name on each transport.

      

      

      
What the adapters may not do

      

        Not one of the three adapters contains SQL, a ranking expression, an ACL predicate, or a traversal.
        Each one marshals a request, calls the same service object, and marshals the response back. That is the
        whole reason the parity check is able to pass — and the reason it would be worth running if it ever failed.
      

    

    

      

        
Resolved tool name per transport

        

        

          AgentCore Gateway does not expose the bare operationId. The exposed name is
          ${targetName}___${operationId} — three underscores. An agent's tool-choice prompt
          sees the prefixed name, and any parity check must strip the prefix before comparing rather than ignore the
          field. operationId stays contract-stable: renaming one is a contract-version change.
        

      

      

        
Shared request · identical on all three

        

      

    

  


  

    

      
Contract parity

      
    

    

    

      The checks that pass are the ones that could have failed. Comparing three transports only to each other passes
      trivially when all three are wrong in the same way, and a check over an empty citation list asserts nothing —
      so scripts/verify_contract_parity.py also recomputes every
      rrf_score from its arm positions and compares each transport against
      fixtures/tool-parity-golden.json.
    

  


  

    
What did not move

    

    

      Every one of these still executes in Aurora PostgreSQL regardless of which transport the agent used to ask.
      Transport identity is recorded in proof.transport_invocations and normalized out of the
      semantic comparison — it is metadata about the call, not part of the answer.
