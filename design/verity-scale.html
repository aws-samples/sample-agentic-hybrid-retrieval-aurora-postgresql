Takes SHARE on the table: reads proceed, writes queue on Lock:relation. This is the incident the corpus documents — and the reason the runbook exists.
CONCURRENTLY (RB-017)
Two table passes, ~2× the build time, no write blocking. Cannot run inside a transaction block; a failed build leaves an INVALID index that must be dropped.
BLUE/GREEN
Build on the green cluster, verify recall against the eval set, then switch. The right answer once the build outgrows any acceptable window.
