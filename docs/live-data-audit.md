# Live-Data Audit

This audit records the participant-data boundary for DAT410. The standing rule
is strict: only evidence generated by the participant's current
`make live-workshop` run may enter `casework`, `retrieval`, agent context,
citations, evaluation, or proof. The Overview graphic is the sole illustrative
exception and never enters the data path.

Workshop bootstrap creates 5,000 disposable customers and 3,000,000 related
orders while the evidence store remains empty. Those rows are operational
substrate, not participant evidence.

## Participant Path

`labs/incident/run_live_workshop.py` is the only incident producer.

**Investigation Evidence**

1. validates the Aurora writer and preloaded operational workload;
2. separately commits the nullable migration column;
3. opens one unbatched backfill transaction;
4. captures the proven transaction-ID lock collision, pool exhaustion,
   pool-boundary timeouts, recovery, statement deltas, and plan checkpoints;
5. records CloudWatch availability or unavailability as supplemental context;
6. builds distinct searchable evidence only from these observations;
7. invokes Cohere Embed through Bedrock for every current chunk; and
8. publishes a receipt only after admission, provenance, and search-index
   checks pass.

**Validation Evidence**

1. requires one Investigation Evidence incident and a participant-reviewed stored proposal;
2. reads the participant-created index definition from Aurora's catalog;
3. records the human approval and observed execution before validating it;
4. captures only new post-index plan and metadata evidence; and
5. publishes an additive validation receipt without revising Investigation Evidence.

No support cases, runbooks, postmortems, customer records, company names,
person names, authored distractors, prior captures, or offline embeddings are
admitted.

## Retired Data Paths

| Retired location or behavior | Participant-path resolution |
|---|---|
| Authored corpus, cases, runbooks, postmortems, people, and companies | Deleted; no authored evidence is admitted |
| Offline PostgreSQL, lock, and statement capture payloads | Deleted; replaced by per-participant capture |
| Seed dump, restore script, or pre-generated vector manifest | Deleted; bootstrap creates only operational workload |
| Fixed-ID multi-terminal incident scripts | Deleted; replaced by one guided orchestrator |
| Release-time capture for later reuse | Deleted; captured evidence is current-run only |
| Generated capture JSON, embedding cache, and indexing receipts | Gitignored and excluded from the source archive |
| Retired locking mechanism | Deleted; replaced by the migration/pool/recovery/plan sequence |
| Performance Insights prerequisite | Removed; source-native PostgreSQL and pool signals prove the core incident |

## Audit Rules

- `make live-workshop` is the sole participant ingestion path.
- Every source URI is under the current capture bundle URI and every
  participant identifier derives from that capture UUID.
- Retrieval accepts only `pg_incident_capture` evidence for the participant
  path.
- Validation Evidence attaches new evidence to the Investigation Evidence incident; it cannot replace,
  tombstone, or alter Investigation Evidence records.
- Archive build rejects generated captures, embedding caches, dumps, database
  files, and retired fixture/seed paths.
- Rehearsal evidence is not compiled into guide defaults, tests, or source
  archives.

The final Aurora rehearsal records its own receipt identifiers and measurements
in the gate-results record. They remain validation evidence, never
participant-path inputs.
